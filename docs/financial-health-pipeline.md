# 재무건전성 수집 파이프라인

- 주기: 1800초마다 정확히 한 종목. 홈의 1~4일차 160개 종목을 대상으로 한다.
- 순서: 미수집 우선, 이후 computed_at이 가장 오래된 종목. 160개를 한 바퀴 처리하는 데 약 80시간.
- 수집: 종목코드 → DART 기업코드 → 최신 보고서·전기 사업보고서·발행주식수. 공시 응답은 최대 24시간 캐시하며 PR 프로세스의 일일 JSON 요청 예산은 4000건.
- 분석: 업종에 따라 Altman Z/Z'' 모델 선택. 금융업은 적용 제외하며, 필수 계정 부족 시 추정하지 않고 사유를 저장한다. 금융업도 하나의 실행 슬롯을 사용한다.
- 반영: 원시 입력·모델·기여 비율·점수·판정·계산 시각을 stock_financial_health에 upsert하고 commit한다. 요약 API 및 상세 API가 이 DB를 조회한다. 홈 배지는 페이지가 보이는 동안 1분마다 조회한다.
- 재시작: DB의 최신 computed_at + 1800초를 기준으로 다음 작업을 재개한다. PostgreSQL transaction advisory lock으로 여러 API 워커의 수집 중복을 방지한다.
- 실패: DART 통신/자료 부족은 계산 불가 사유로 기록하고 다음 슬롯에서 다음 종목으로 진행한다. 예기치 않은 예외는 로그에 남기고 30분 후 재시도한다. 재시작·예외·운영 중단에 따라 예정 시각은 지연될 수 있다.
- 운영 확인: GET /market/financial-health/summary의 pipeline.enabled, interval_seconds, batch_size, next_due_at과 last_computed_at 확인. 데이터가 오래된 종목은 상세의 computed_at 및 공시 보고서 기준을 함께 확인한다.
- 전제: 이 파이프라인 외의 수동 CLI 수집은 자동 주기를 앞당기는 용도로 사용하지 않는다. 수동 수집도 DB 갱신 시각을 변경하므로 다음 자동 실행 시각에 반영된다.
